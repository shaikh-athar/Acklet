## 1. Architectural Overview

Traditional barcodes generated by Acklet remain 100% client-side in browser memory with zero network calls.
**Temporary Barcodes** introduce a secure, server-enforced lifecycle:
1. The barcode encodes a cryptographically random verification token (or verification URL).
2. The server strictly enforces validity using an injectable UTC `Clock`. Client-only expiry is prohibited.
3. Content is revealed only while the token is active. Once expired or deactivated, confidential content is permanently withheld from public check responses.
4. Expired records are automatically removed by a background purge worker.

> [!NOTE]
> Barcode Generator and QR Code Generator maintain clean surface separation. Barcode Generator exclusively supports 1D Linear and 2D Industrial matrix barcodes (`code128`, `datamatrix`, `aztec`, `pdf417`). Temporary QR Codes are managed in QR Code Generator.

```
[ User Browser ]
   │
   ├─► Standard / Bulk Barcodes ──► 100% In-Browser Memory (Zero Server Calls)
   │
   └─► Temporary Barcodes ───────► Spring Boot Backend (/api/v1/temp-codes)
                                         │
                                         ├─► Crockford Base32 Token (80 bits)
                                         ├─► AES-256-GCM Encrypted Content
                                         ├─► UTC Expiry Enforcement
                                         └─► Automated Scheduled Purge
```

## 2. Modes and Content (Simplified & Unified Pipeline)

### 2.1 Content Preservation
In the simplified pipeline, enabling "Temporary code" preserves the user's selected symbology and barcode value without altering the input schema:
- The barcode format selector and value input fields remain **always visible and active**.
- All supported barcode formats (Code 128, EAN-13, Code 39, UPC-A, Data Matrix, etc.) remain accessible without forced switching.
- Real content is rendered in the live preview continuously. The "Sample layout" watermark, sample notices, and standing connection error banners have been removed.

### 2.2 Simplification & Streamlining (What Was Removed and Why)
1. **Removed "Show when checked" (Message / Link / Reference only)**: Content is derived directly from the barcode's real value input.
2. **Removed "Message text" box and character counters**: Unnecessary duplicate fields eliminated.
3. **Removed "Encode as" (Link / Code) tab toggles**: Streamlined into an automated verification link structure.
4. **Removed "Sample layout" badge and banner**: The preview area displays the actual barcode matching the user's styling, format, and value.
5. **Removed standing connection warnings**: Errors are surfaced on-demand only when a creation request actually fails.

### 2.3 Expiry Configuration
When "Temporary code" is enabled, only the compact **"Expires after"** section is rendered below the toggle:
- Preset buttons: 15 minutes, 1 hour, 6 hours, 24 hours (default), 7 days, 30 days.
- Custom options: Duration (value + unit) or Until (datetime picker) with bounds validation (1 minute minimum, 365 days maximum).
- Optional label caption: "Valid until [Date]".

## 3. Expiry and Scheduling

### 3.1 Presets & Custom Configuration
- **Presets**: 15 minutes, 1 hour, 6 hours, 24 hours (default), 7 days, 30 days.
- **Custom Choice**:
  - **Duration**: Number plus unit (minutes, hours, or days).
  - **Until**: Date and time picker.
- **Configured Limits**:
  - Minimum: 1 minute (*"Choose a time at least 1 minute from now."*)
  - Maximum: 365 days (*"The maximum is 365 days."*)
- **Timezone Handling**:
  - Computed and stored strictly in UTC.
  - Displayed in the user device timezone with full timezone names (e.g. *India Standard Time*, *Eastern Daylight Time*).

### 3.2 Optional Label Expiry Caption
- Optional toggle: *"Show expiry on the label"*
- Renders caption under barcode: *"Valid until [Formatted Date]"*.
- Clarifying notice: *"If you extend the code later, the printed text does not change."*

## 4. Verification Page (`/v/{token}`)

The public verification page handles all code statuses with clear, friendly copy:

| Status | Visual Presentation | Behavior |
| :--- | :--- | :--- |
| **Valid** | Green checkmark, active badge, live countdown | Displays message, destination confirmation card, or reference. Countdown ticks down every second and transitions automatically to Expired at 0. |
| **Expired** | Amber clock, expired badge | *"This code expired on [Date]. The content is no longer available."* |
| **Deactivated** | Grey slashed circle | *"This code was deactivated by its creator."* |
| **Not Found** | Yellow alert | *"This code does not exist. Check the link or scan again."* |
| **Rate Limited** | Orange warning | *"Too many checks. Please wait a minute and try again."* (HTTP 429) |
| **Connection Error**| Red warning | *"Could not check this code. Check your internet connection and try again."* |

### Abuse Reporting
- Users can flag abusive codes via an inline modal.
- Reasons: Malware or phishing, Inappropriate content, Spam or misleading, Other.
- Submissions hash the reporter's IP with a server pepper (zero plaintext IP storage).

## 5. Owner Management & Dashboard

- **Full-Width Dashboard**:
  - The **Temporary** tab functions as a full-width dashboard (`grid-template-columns: 1fr` without the side preview card).
  - Header counters display live totals: **Active**, **Expiring soon**, and **Expired**.
  - Search input with debounce filters codes by name.
  - Status and Sort filters powered by Acklet's canonical custom popover dropdowns (`Status`: All, Active, Expiring soon, Expired, Deactivated; `Sort`: Newest first, Expiring soon) with dual-theme contrast.
  - Responsive: Desktop renders a comprehensive data table; mobile/narrow viewports render stacked cards.
- **Batch Grouping & Bulk Support**:
  - Temporary codes generated via the **Bulk** tab share a `batchId` and are grouped into expandable batch cards.
  - Batch header summarizes item count, expiry, and combined status.
  - Batch actions: **Extend all**, **Expire all**, **Delete all**, and **Download all** (ZIP archive including SVG vector barcodes and `manifest.csv`).
  - Idempotent generation: batches submit an `idempotencyKey` preventing duplicate server records on retry.
- **Single Item Actions**:
  - **Copy link**: Copies verification link or code to clipboard with visual copy confirmation.
  - **Open check page**: Launches public verification view in a new tab (available for launchable content).
  - **Download SVG**: Downloads lossless vector barcode.
  - **Extend**: Opens extension modal with +1 hour, +6 hours, +24 hours, or +7 days presets.
  - **Expire Now**: Immediately deactivates an active code.
  - **Rename**: Inline dialog to update descriptive label.
  - **Delete**: Permanently purges record from server.

### 5.1 Launch Icon (`arrow-up-right`) & Check Action Rule for Barcodes

Unlike 2D QR codes which have explicit semantic types (URL, Wi-Fi, vCard), 1D linear and 2D industrial barcodes typically encode raw strings, inventory identifiers, SKU numbers, or serial strings.

- **Content Value Inspection**: The launch icon (`arrow-up-right`) and external "Check page" action button are rendered **only when the barcode's content or payload is an authentic redirectable link or URI scheme**:
  - Valid web URLs (`http://`, `https://`)
  - App scheme links (`market://`, `itms-apps://`)
  - Contact URI schemes (`mailto:`, `tel:`, `sms:`)
  - Crypto/Geo schemes (`geo:`, `bitcoin:`, `ethereum:`, `solana:`)
- **Plain Numbers & Text**: Barcodes containing plain alphanumeric strings, product codes (e.g. `ACKLET-PKG-9821`, `1234567890`), or raw identifiers **do not display a launch icon**, preventing misleading user affordances.
- **Surface Uniformity**: Applied consistently across the Temporary table format pills, single/batch cards, and mobile overflow actions.

- **Anonymous Device Ownership**:
  - Device identified by a cryptographically random owner token: `tok_` prefix followed by 32 Crockford Base32 characters.
  - Returned in `X-Owner-Token` response header on initial creation.
  - Saved in browser `localStorage` (`acklet_barcode_owner_token`).
  - Stored in backend as `SHA-256(owner_token)`. Plaintext owner token is never persisted on server.

## 6. Security Model & Data Protection

| Security Vector | Implementation Detail |
| :--- | :--- |
| **Token Entropy** | 16 Crockford Base32 characters (excluding `i, l, o, u`) = $16 \times 5 = 80$ bits entropy. |
| **Token Lookup** | Lookups query `token_hash = SHA-256(token)`. Plaintext token is never queried. |
| **Encryption at Rest** | Confidential `token` and `content` columns are encrypted with AES-256-GCM via `ShortenerEncryptedStringConverter`. |
| **No-Store Caching** | Verification endpoints return `Cache-Control: no-store, no-cache, must-revalidate, max-age=0` and `Pragma: no-cache`. |
| **Safe Browsing / URL Sanitization** | Links require HTTP/HTTPS, reject private/loopback IP ranges (`127.0.0.1`, `10.0.0.0/8`, `192.168.0.0/16`), check URL length ($\le 2048$), and validate against safe browsing blocklists. |
| **Rate Limiting** | Create endpoint: 20/hr per IP/owner. Verify endpoint: 60/min per IP. |
| **Automated Purge** | Nightly cron job deletes records where `purge_at <= Clock.instant()` (default: 30 days post-expiry). |

## 8. Database Schema (`V58__temporary_barcodes.sql`)

```sql
CREATE TABLE IF NOT EXISTS temp_codes (
    id UUID PRIMARY KEY,
    owner_token_hash VARCHAR(64) NOT NULL,
    user_id UUID,
    name VARCHAR(100) NOT NULL,
    token_hash VARCHAR(64) NOT NULL UNIQUE,
    encrypted_token TEXT NOT NULL,
    payload_mode VARCHAR(16) NOT NULL,
    content_type VARCHAR(32) NOT NULL,
    content TEXT,
    reference VARCHAR(64),
    barcode_format VARCHAR(32) NOT NULL,
    show_expiry_on_label BOOLEAN NOT NULL DEFAULT FALSE,
    created_at TIMESTAMP WITH TIME ZONE NOT NULL,
    expires_at TIMESTAMP WITH TIME ZONE NOT NULL,
    status VARCHAR(16) NOT NULL,
    check_count BIGINT NOT NULL DEFAULT 0,
    last_checked_at TIMESTAMP WITH TIME ZONE,
    purge_at TIMESTAMP WITH TIME ZONE NOT NULL,
    deleted_at TIMESTAMP WITH TIME ZONE
);

CREATE TABLE IF NOT EXISTS temp_code_reports (
    id UUID PRIMARY KEY,
    code_id UUID NOT NULL REFERENCES temp_codes(id) ON DELETE CASCADE,
    reporter_ip_hash VARCHAR(64) NOT NULL,
    reason VARCHAR(64) NOT NULL,
    comment VARCHAR(500),
    created_at TIMESTAMP WITH TIME ZONE NOT NULL
);
```

## 9. Design System & Dual-Theme High Contrast

All temporary barcode components comply with the canonical Acklet Design System tokens (`client/packages/tool-shell/src/styles/tokens.css`) and WCAG AA contrast standards ($\ge 4.5:1$) across both Light and Dark themes:

- **Surface Tokens**: Cards use `var(--bg-surface, #1e1e24)` in Dark mode and `#FFFFFF` with hairline borders in Light mode (`:host-context([data-theme="light"])`).
- **Form Controls & Inputs**: Text fields, textareas, and selects use deep navy/slate backgrounds `var(--bg-base, #121216)` in Dark mode and `#F8FAFC` in Light mode, avoiding unstyled white backgrounds.
- **Segmented Tracks**: Segmented controllers use `var(--bg-base, #121216)` in Dark mode with primary accent active buttons (`var(--tool-accent, #2563EB)`).
- **Preview Canvas**: The preview stage uses a transparent background matching the surrounding card container, with high-contrast label rendering for scan clarity.
